# 联赛视频

把一场已经打完的联赛做成视频。平台负责素材、排版和渲染，你负责写脚本：规则介绍、每个选手的介绍、精彩对局的解说。视频没有标题页，也不展示用户的话。开场阵容底部和片尾的平台署名（RTS Arena）由平台固定加上，去不掉；选手页按联赛名次倒着出场，不用自己排。渲染用本机的 Chrome 或 Edge，不用装别的。

## 步骤

### 1. 准备联赛

选手文件在压缩包里时先解压。Windows 上用系统自带的 `C:\Windows\System32\tar.exe -xf 包.rar`（Git Bash 里的 tar 解不了 RAR；包名是中文时先复制成英文名再解）。

还没有联赛就先跑一场（选手文件放在当前目录，联赛名字就是文件名去掉 `.ts`；规则包的名字用 `rts-arena list` 查）：

```bash
rts-arena league <规则包> 选手A.ts 选手B.ts 选手C.ts --per-pair 20 --out league
```

每对 10～20 局：局数多了才有爆冷、逆转可挑。一局一般一两秒，3 人每对 20 局（60 局）大约要 1～2 分钟、长的规则包更久——命令超时设长一点（比如 10 分钟）或者放后台跑。输出每局一行，看最后的排名、统计和精彩对局就行。

### 2. 导出视频目录

```bash
rts-arena video-init league my-video --portraits <选手形象图目录>
```

用户给了选手形象图（立绘）的目录就用 `--portraits`：按文件名对应选手（文件名里只出现在一个选手名字里的词算数，比如 `claude fable.png` 对上 `Fable5.1`），复制进视频目录的 `portraits/`、填进 `script.json` 的 `portrait`。选手页背后放半透明的半身像，精彩对局里主基地换成从它裁的头像。用户的要求（比如"请把 xx 称作 yy"）照做就行，可以写进 `--about`。

用户说了联赛数据里没有的背景——外号对应哪个模型、用什么编程工具写的、以前的成绩——就用 `--about "…"` 一起写进去，PROMPT.md 里会单独列出来。**只写用户真的说过的话**，格式像这样：`--about "<外号> 是 <模型名> 写的（编程工具 <工具名>）；<用户说的以前的成绩>"`，尖括号里换成用户说的内容，没说的就不写。

第一个参数是联赛汇总文件或者它所在的目录，第二个是要建的目录。只写一个还不存在的名字时，它就是要建的目录，联赛自己找（依次找 `./replays`、当前目录和下一层子目录里最新的一场）。目录里有：

- `RULES.md`：规则包的规则说明（写规则介绍用）
- `PROMPT.md`：给你的完整说明（视频结构、怎么写、字数上限、脚本格式、命令），以及这场联赛的数据：排名、每个选手的文件和代码指标、**联赛速查**（最快 / 最久的局、每人赢了谁输给谁、爆冷、克制环、比分最接近的局、规则包事件最多的局）、精彩对局、全部对局
- `bots/`：每个选手的代码（文件名不变）
- `reports/`：几局的战报（精彩对局、每个选手赢得最快的一局、最长的一局）
- `portraits/`：对上名字的选手形象图（给了 `--portraits` 才有）
- `script.json`：待填的脚本（形象图已经填进 `portrait`）
- `brief.json`：同样的数据（JSON，给程序用的，不用读）

### 3. 照 PROMPT.md 写 script.json

先完整读 `PROMPT.md`，再读 `bots/` 里每个选手的代码，需要时看 `reports/` 的战报。只用这个目录里的东西就够了，不用去读平台源码。要点（PROMPT.md 里有详细的）：

- 写开场的 `hook.text`（30 字以内）：视频第一帧就是选手立绘阵容加这句大字（底部小字是平台署名），要像短视频标题，一句话点出冲突或悬念，抓住前 3 秒
- 照目录里的 `RULES.md` 写 `rules`：给没玩过的观众讲清楚怎么赢、最关键的机制（视频开头的规则介绍，配地图和单位图例）。别写"和某某规则包一样""在某某的基础上"，观众不一定玩过，把要用到的规则直接简要讲出来
- 文件名常见写法是 `模型名-编程工具.ts`，据此写显示名和一行小字；拆不开就照原样
- 选手介绍从三处来：代码、选手的参赛报告（`bots/<名字>.REPORT.md`，有的话）和这场联赛的对战数据；写出每个选手的风格（tagline 加 intro 每人 4～5 句、180～260 字）；报告里的自测成绩是对参考 bot 打的，别当成这场联赛的；介绍要有依据，数字照抄，不编造
- 先看「联赛速查」再挑精彩对局（3～10 局，用户说了要几局就挑几局），排成一条故事线；每局的标题和解说照这一局写（对阵双方、谁赢了），别从别的视频的脚本里抄；解说里说的事要在战报里查得到（规则包的事件在战报的关键事件里，带"（规则包）"）
- `tagline`、精彩对局的 `title` 和 `commentary`、`outro` 是粗体，别写"一"（像破折号），数量写阿拉伯数字
- 出预览后看精彩对局里的头像：脸没在框里就给那个选手写 `avatar`（[脸中心 x, 脸中心 y, 边长]，按图的宽、高算比例）

### 4. 在目录里出预览、出视频

```bash
cd my-video
rts-arena video --lint                      # 只核对脚本：格式、每段字数和上限、时间表（不出图），字数对了再往下
rts-arena video --preview auto              # 每段各画一张（PNG，放在 preview/ 里，另有一张总览拼图），先看总览再逐张细看
rts-arena video --check auto                # 出视频（默认输出成 <规则包>联赛.mp4，--out 可以改），并从成品里每段截一张检查（也放在 preview/ 里）
rts-arena video --vertical --check auto     # 可选：竖屏版（1080×1920，每个选手的介绍接着他的一局高光对局），给短视频平台
```

每次运行都会列出每段从第几秒到第几秒，要细看某一段就 `--preview 秒,秒`。脚本格式不对、字数超了，命令会列出所有问题，照着改；输出里的"提醒"（比如粗体字段里的"一"）不挡出视频，但也照着改。预览图要逐张打开看：字有没有挤出画面、介绍是不是太长、名字和颜色对不对、头像有没有框住脸。第一次出预览要读完全部回放算雷达图和胜率模型（几十秒），之后用缓存。

### 5. 交付

告诉用户视频在哪、多长、讲了什么（几个选手、挑了哪几局、为什么），以及介绍依据了哪些代码特征。
