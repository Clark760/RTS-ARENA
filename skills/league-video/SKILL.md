# 联赛视频

把一场已经打完的联赛（`rts-arena league` 生成的 `*.series.json`）做成视频。视频依次是：

1. **片头平台署名**（RTS Arena，渲染器固定加，去不掉）
2. 标题、用户的原话、你对原话的解读
3. 每个选手的介绍（你写）+ 代码开头的注释和代码指标（平台自动配）
4. 联赛排名
5. 精彩对局：标题卡（看点、你的解说）+ 回放画面（整局压缩成 10～20 秒，右边是双方兵力和战况）
6. 你写的一句总结 + **片尾平台署名**（渲染器固定加）

渲染用本机的 Chrome 或 Edge（无头模式），不用装别的。

## 步骤

### 1. 准备联赛

还没有联赛就先跑一场。选手文件放在当前目录，按文件名排上：

```bash
rts-arena league <规则包> 选手A.ts 选手B.ts 选手C.ts --per-pair 6 --out league
```

每对局数多一点（6 局以上），精彩对局才挑得出来。联赛名字就是文件名去掉 `.ts`。

### 2. 拿素材包

```bash
rts-arena video-brief league --out brief.json
```

不写目录就找 `./replays` 里最新的一场联赛。`brief.json` 里有：

- `players`：每个选手的联赛名字、文件路径、文件名拆开的几段（`fileNameParts`）、排名和战绩、对每个对手的胜平负、每局平均数据、出错次数，以及 `code`——代码的客观指标：行数、注释比例、注释里汉字的比例、文件开头的注释（`header`）、函数和类型的个数、顶层状态变量、常量参数、写法特征（attackMove / attack 的次数、类型化数组、自己写寻路、状态机、"实测""调参"这类注释、注释里的感叹号、中英对照的标题、版本号……）
- `highlights`：联赛挑的精彩对局（局号、谁对谁、谁赢、看点）
- `scriptTemplate`：待填的脚本
- `rules`：写脚本的规矩

### 3. 读代码

`brief.json` 只给了指标。每个选手的代码文件都要打开读一遍（至少开头的注释和主要的决策逻辑），弄清它的打法、它自己声称的绝招、写法上的特点。

### 4. 写脚本

把 `scriptTemplate` 抄一份改成 `script.json`。要分析三样东西：

- **用户的原话**：原样放进 `userText`。弄懂它在说什么（调侃谁、有什么梗、立场站在哪边），在 `theme` 里用一句话点出来；整个视频的语气跟着它走。
- **选手的文件名**：常见写法是 `模型名-编程工具.ts`，比如 `GPT6.1sol-codex.ts` 是"在 codex 里用 GPT 6.1 sol 写的"。据此写 `displayName`（模型名，加上空格好读）和 `byline`（编程工具、出品方之类）。拆不开就照原样用，不要瞎猜。
- **代码风格**：结合 `code` 指标和你读到的代码，写出这个选手"是什么样的作者"：精打细算还是大开大合、工程化还是文案化、靠调参还是靠架构、它自称的绝招和联赛里实际的表现对不对得上。

每个选手：

- `tagline`：一句话定位，最多 30 字
- `intro`：2～4 句，每句最多 50 字。要有依据：用户原话、文件名、代码、联赛成绩里看得到的才写，数字照抄素材包，不编造没发生的事
- 成绩差的写它的特点和输在哪，别贬低；语气可以跟着用户原话调侃

精彩对局 `highlights`：从素材包的 `highlights`（或者 `rts-arena report <回放>` 看过的其他局）里挑 2～3 局，按想讲的故事排顺序。`title` 最多 24 字，`commentary` 一句话最多 80 字，说清这局看什么。说到的事要在那局的看点或战报里查得到。

`outro`：一句总结，最多 60 字，可以呼应用户原话。

**平台署名**：片头、片尾的 RTS Arena 署名由渲染器自动加，脚本里不用写，也去不掉；介绍和解说里不要冒充平台的口吻。

### 5. 先出预览图检查

```bash
rts-arena video league --script script.json --out 联赛.mp4 --preview 2,9,16,40,80
```

`--preview` 只画这几秒的画面（PNG，存在视频文件名旁边），不出视频。逐张打开看：字有没有挤出画面、介绍是不是太长、选手颜色和名字对不对。脚本格式不对时命令会列出所有问题，照着改。

### 6. 出视频

```bash
rts-arena video league --script script.json --out 联赛.mp4 --check 3,30,60
```

出完会用浏览器把成品解码一遍，报时长和尺寸；`--check` 从成品里截这几秒的图，打开看一眼确认画面正常。一般 1～2 分钟长、几 MB 到十几 MB。

### 7. 交付

告诉用户视频在哪、多长、讲了什么（几个选手、挑了哪几局精彩对局、为什么），以及你在介绍里依据了哪些代码特征。

## 脚本格式

```json
{
  "title": "视频标题（最多 24 字，可省）",
  "userText": "用户的原话（最多 120 字）",
  "theme": "对原话的解读、一句话导语（最多 60 字）",
  "players": [
    {
      "name": "联赛里的名字（和文件名去掉 .ts 一样，必须完全一致）",
      "displayName": "显示名（最多 28 字，英文模型名比汉字窄）",
      "byline": "一行小字（最多 30 字）",
      "tagline": "一句话定位（最多 30 字）",
      "intro": ["介绍 2～4 句", "每句最多 50 字"]
    }
  ],
  "highlights": [{ "index": 18, "title": "这局的标题（最多 24 字）", "commentary": "一句话解说（最多 80 字）" }],
  "outro": "一句总结（最多 60 字）"
}
```

所有选手都要写，顺序就是视频里出场的顺序。`highlights` 不写就用联赛挑的前 3 局、不带解说。
