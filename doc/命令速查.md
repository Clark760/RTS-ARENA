# 命令速查

`rts-arena` 的全部命令和常用选项，按要做的事分组。每个命令的完整选项用 `rts-arena help <命令>` 看，比如 `rts-arena help league`。还没装好的话，先看 [入门教程](入门教程.md)。

## 最常用的几条

在 bot 目录里（有 `arena.json` 的目录）：

```bash
rts-arena check                    # 类型检查 + 在每个位置试打，有报错先修
rts-arena run --games 10 --quiet   # 和基准 bot 打 10 局，看胜率
rts-arena league                   # 和所有参考 bot 循环对打，看输给了谁
rts-arena report                   # 最新一局的文字战报
rts-arena view                     # 网页播放器：看回放、在网页上开比赛
```

## 先弄清三件事

**在不在 bot 目录里**。bot 目录是 `rts-arena init` 建的、有 `arena.json` 的目录，里面记着用哪个规则包、自己的 bot 是哪个文件。在 bot 目录里，命令自动用这个规则包，你的 bot 自动上场；不在 bot 目录里，就要把规则包和所有参赛的 bot 写全。

| | 在 bot 目录里 | 在别的目录 |
|---|---|---|
| 检查 | `rts-arena check` | `rts-arena check koth a.ts` |
| 打一局 | `rts-arena run rush`（你的 bot 打 rush） | `rts-arena run koth a.ts rush` |
| 联赛 | `rts-arena league`（你的 bot 和全部参考 bot） | `rts-arena league koth a.ts b.ts c.ts` |

**规则包怎么写**。平台自带的写名字：`annihilation`、`koth`、`frontier`……全部名字用 `rts-arena list` 看，每个怎么玩见 [规则包介绍](规则包介绍.md)。自己写的规则包写目录路径，要带 `./`：`./my-rules`（不带会被当成自带规则包的名字）。

**bot 怎么写**。写文件路径（`a.ts`、`../other/bot.ts`），或者写参考 bot 的名字：`baseline`（每个规则包都有的基准 bot）、`idle`（什么都不做），以及规则包自带的参考 bot（`rush`、`expand`……，用 `rts-arena list <规则包>` 看）。

## 建 bot 目录

| 命令 | 做什么 |
|---|---|
| `rts-arena init <规则包>` | 在当前目录建 bot 目录：`arena.json`、`bot.ts` 模板、说明书 `PROMPT.md`、接口 `arena.d.ts`、`tsconfig.json` |
| `rts-arena init <规则包> <目录>` | 在指定目录建 |
| `rts-arena init` | 在 bot 目录里重新生成说明书和接口，不动 `bot.ts`。平台升级后跑一次 |
| `rts-arena init <别的规则包>` | 在 bot 目录里换规则包 |
| `rts-arena docs <规则包> [--out 目录]` | 只生成说明书和接口，不建 bot 目录（默认放在 `./out/<规则包>/`） |

## 检查和打比赛

| 命令 | 做什么 |
|---|---|
| `rts-arena check` | 检查自己的 bot：类型检查，再在每个位置上和不动的对手试打 300 tick |
| `rts-arena check --ticks 1000` | 试打得久一点 |
| `rts-arena run` | 和 baseline 打一局 |
| `rts-arena run rush` | 和指定的对手打一局；多人局的规则包可以写几个对手，一起打一局 |
| `rts-arena run --games 10` | 连打 10 局，最后报胜率和 95% 区间；同一个种子换边各打一次 |
| `rts-arena run <规则包> old.ts rush` | 写上规则包就是自己指定所有参赛的 bot（比如拿旧版本打参考 bot） |

`run` 的选项：

| 选项 | 作用 |
|---|---|
| `--games N` | 连打 N 局，最后报胜率 |
| `--seed N` | 种子（默认随机）。同一个种子就是同一张地图、同样的随机 |
| `--ticks N` | 打到第 N tick 就结束，按规则包时间到了的规则判胜负。只看开局、经济时用 |
| `--quiet` | 每局只打一行，最后的胜率照常打印 |
| `--teams 2v2` | 分队（规则包要支持），按写的顺序分：前 2 个一队、后 2 个一队 |
| `--out 路径` | 回放放哪，默认 `./replays`；单局时也可以写 `.json` 文件名 |
| `--no-check` | 跳过类型检查 |
| `--json` | 每行输出一个 JSON 事件，给程序读 |

回放和日志都在 `./replays`：每局一个回放文件，每个 bot 一份只有它自己信息的日志。

## 联赛

| 命令 | 做什么 |
|---|---|
| `rts-arena league` | 你的 bot 和所有参考 bot 循环对打，参考 bot 之间也打 |
| `rts-arena league rush expand` | 你的 bot 和写的这几个循环对打 |
| `rts-arena league --focus --per-pair 10` | 只打你的 bot 对每个参考 bot，参考 bot 之间不打 |
| `rts-arena league koth a.ts b.ts c.ts --per-pair 20` | 指定的几个 bot 循环对打，每对 20 局 |
| `rts-arena league melee a.ts b.ts c.ts d.ts e.ts --size 4` | 多人联赛：每局 4 个人 |
| `rts-arena league melee a.ts b.ts c.ts d.ts --teams 2v2` | 分队联赛 |

`league` 的选项：

| 选项 | 作用 |
|---|---|
| `--per-pair N` | 两人局每对打几局（默认 4）。局数少时排名误差很大，认真比较时用 10～20 |
| `--per-table N` | 同上，多人局时是每桌打几局（默认轮换座位一圈） |
| `--size K` | 每局几个人（默认 2） |
| `--tables M` | 多人局组合太多时抽几桌（默认组合不超过 20 桌就全打） |
| `--teams 2v2` | 分队联赛；`--partners mixed` 轮换搭档（默认），`--partners same` 每队由同一个 bot 组成 |
| `--focus` | 只打第一个 bot 对其余每个，其余的之间不打（两人局用） |
| `--seed`、`--out`、`--no-check`、`--json` | 和 `run` 一样 |

联赛最后会打印这几样，全部结果还另外记在回放目录的 `*.series.json` 里（做视频用的就是它）：

- **排行榜和对阵表**：胜 1 分、平 0.5 分；多人局第一名 1 分、最后一名 0 分、中间平分。
- **等级分和把握度**：等级分从 1500 起，把全部对局一起算，和打的先后顺序无关；把握度是「排在上面的确实更强」有多大把握。
- **统计**：每个 bot 每局平均的采集、损失、击杀、燃料、报错，还有每个座位的得分率（看地图偏不偏）。
- **精彩对局**：逆转、两边都伤得重、大战、险胜、爆冷，附看点和回放文件名。一边倒的屠杀不算。

## 看结果

| 命令 | 做什么 |
|---|---|
| `rts-arena report` | `./replays` 里最新一局的文字战报：每隔一段时间的经济、兵力、建筑，关键事件、战斗、损失，最后是「可能的问题」 |
| `rts-arena report <回放文件>` | 看指定的一局 |
| `rts-arena report --player 1` | 从 1 号座位的角度写（默认是你的 bot 坐的座位） |
| `rts-arena report --every 200` | 每 200 tick 抽一行（默认按整局长度挑，大约 10 行） |
| `rts-arena report --full` | 事件和战斗全部列出，不省略中间的 |
| `rts-arena view` | 网页播放器，看 `./replays` 里的回放，端口 5180 |
| `rts-arena view <回放目录> --port 5181 --open` | 看别的目录、换端口、起来后自动打开浏览器 |
| `rts-arena map` | 画出开局地图；`--seed N` 看某个种子的地图（地图随种子随机的规则包每局不一样） |
| `rts-arena list` | 列出所有规则包和现成的 bot |
| `rts-arena list <规则包>` | 列出这个规则包的参考 bot 和各自的打法 |

播放器有两个页签：**回放**（空格播放、←/→ 单步、拖动平移、滚轮缩放，点实体看它的命令，右边看 bot 的日志和报错）和 **对战**（在网页上选规则包和 bot 开比赛或联赛，底下跑的就是 `run` 和 `league`）。

## 联赛视频

详细的见 [联赛视频指南](联赛视频指南.md)。

| 命令 | 做什么 |
|---|---|
| `rts-arena video-init <联赛> <目录> --text "原话" --about "背景"` | 从一场联赛导出视频目录：说明书 `PROMPT.md`、选手代码、战报、待填的 `script.json`。`<联赛>` 是 `*.series.json` 或它所在的目录 |
| `rts-arena video --lint` | 在视频目录里：只核对脚本，列出字数和每段的时间表 |
| `rts-arena video --preview auto` | 每段出一张预览图，放在 `preview/` 里；`--preview 12.5,40` 只看这几秒 |
| `rts-arena video --check auto` | 出视频，再从成品里每段截一张图检查；`--out 名字.mp4` 改输出文件名 |
| `rts-arena video-brief <联赛> [--out 文件]` | 只要联赛视频的素材包（JSON），给自己写程序用 |

渲染用本机的 Chrome 或 Edge。装在别处时用环境变量 `RTS_ARENA_BROWSER` 或者 `--browser <路径>` 指定。

## 写规则包

详细的见 [规则包编写指南](规则包编写指南.md)。

| 命令 | 做什么 |
|---|---|
| `rts-arena new-rules my-rules` | 建一个能直接跑的示例规则包，从它改起 |
| `rts-arena new-rules my-rules`（目录已存在） | 只刷新平台提供的文件（`RULESET.md`、`api/`），不动你的代码 |
| `rts-arena check ./my-rules` | 检查规则包：类型、加载、各种人数试打、打一整局看结束判定 |
| `rts-arena run ./my-rules baseline baseline --games 4` | 用参考 bot 试打几局 |
| `rts-arena league ./my-rules baseline rush expand --per-pair 10` | 看几种打法谁强，调数值用 |
| `rts-arena init ./my-rules my-bot` | 给它建 bot 目录，之后照常 `check`、`run`、`view` |

## 安装和更新

| 想做的事 | Windows 双击 | 命令行 |
|---|---|---|
| 第一次安装 | `start.bat` | `git clone …`、`npm install`、`npm install -g .`（见 [README 的安装](../README.md#安装)） |
| 更新平台 | `update.bat` | 在平台目录里 `git pull && npm install` |
| 更新后刷新 bot 目录的说明书 | `update.bat` 会刷新 `my-bot` | 在 bot 目录里 `rts-arena init` |

## 常用组合

| 想做的事 | 怎么做 |
|---|---|
| 改了一版，看有没有变强 | 旧版另存成 `old.ts`，然后 `rts-arena league <规则包> bot.ts old.ts rush expand --per-pair 10` |
| 两个版本在同一批地图上比 | 各跑一次 `rts-arena league <规则包> <版本> <对手...> --focus --per-pair 10 --seed 7`，种子写同一个 |
| 看排名的误差有多大 | 同一个 bot 在联赛里写两次（名字会带 #编号），两份副本差多少，误差就有多大 |
| 只调开局和经济 | `rts-arena run --games 10 --ticks 1500 --quiet`，再 `rts-arena report` 看采集 |
| 复现某一局 | 回放文件名里有种子（`-s41-` 就是种子 41），`rts-arena run <对手> --seed 41 --games 2` 在这张地图上换边各打一次 |
| 看某一局为什么输 | `rts-arena report <回放文件>` 看「可能的问题」，再 `rts-arena view` 打开那局看 |
| 让大模型自己迭代 | 把 bot 目录交给它，让它先读 `PROMPT.md`，每改一版都跑 `check`、`run --games 10`、`league` 再改 |
