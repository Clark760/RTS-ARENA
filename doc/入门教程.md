# 入门教程

大约 20 分钟：装好平台，建一个 bot 目录，跑第一局，看回放和战报，再把 bot 交给大模型去写，最后开一场联赛。

## 1. 先认识几个词

| 词 | 意思 |
|---|---|
| **规则包** | 一种玩法：地图、单位、怎么赢都由它定。自带 10 种，比如「歼灭」（拆掉对方主基地就赢）、「夺点」（占住中间的控制点计分）。 |
| **bot** | 你写的 TypeScript 文件，控制一方的全部单位。每隔几个 tick 平台调用它一次，它看局面、下命令。 |
| **参考 bot** | 每个规则包自带的几个对手，打法各不一样，用来陪练。`baseline` 是均衡的基准，`idle` 什么都不做。 |
| **tick** | 游戏时间的单位，1 秒 = 10 tick。 |
| **燃料** | bot 每次被调用时能用的计算量，用完这次就被打断。见下面第 5 步的说明。 |
| **回放** | 每局一个文件，记下整局的过程，可以在网页播放器里看，也可以生成文字战报。 |
| **联赛** | 一组 bot 循环对打，出排行榜。判断 bot 强不强看联赛，别只看一两局。 |

## 2. 安装

照 [README 的「安装」](../README.md#安装) 二选一装好。装好后运行：

```bash
rts-arena help
```

能看到命令列表就说明装好了。提示找不到 `rts-arena` 时，回去看安装最后一步 `npm install -g .` 有没有成功。

## 3. 看看有哪些规则包

```bash
rts-arena list
```

每个规则包一行：名字、几个人打、一句话玩法，下面是它的参考 bot。每个规则包的详细玩法见 [规则包介绍](规则包介绍.md)。想看某个规则包的参考 bot 都怎么打：

```bash
rts-arena list annihilation
```

地图每局按种子随机生成，两边对称。想看某个种子的开局地图：

```bash
rts-arena map annihilation --seed 7
```

## 4. 建 bot 目录

第一次建议用「歼灭」：规则最简单，采矿、出兵、拆家。

```bash
mkdir my-bot
cd my-bot
rts-arena init annihilation
```

目录里多了这些文件：

| 文件 | 是什么 |
|---|---|
| `PROMPT.md` | 完整说明书：玩法、开局地图、参考 bot、全部接口、怎么测试。写 bot 只看它就够了 |
| `bot.ts` | 你的 bot。现在是个最简单的模板：闲着的工人去采最近的矿，不生产也不打仗 |
| `arena.d.ts` | 类型接口，编辑器靠它做提示和检查 |
| `arena.json` | 记着这个目录用哪个规则包、bot 是哪个文件 |
| `tsconfig.json` | TypeScript 配置 |

## 5. 检查，然后跑第一局

```bash
rts-arena check
```

先做类型检查，再让 bot 在每个出生位置上和不动的对手试打 300 tick：

```
类型检查通过
bot.ts（位置 P0，种子 1）：试打 300 tick 通过（调用 61 次，燃料最高 0，被拒命令 0）
bot.ts（位置 P1，种子 2）：试打 300 tick 通过（调用 61 次，燃料最高 0，被拒命令 0）
```

有报错或「被拒命令」不是 0，先修好再往下走。然后和基准 bot 打一局：

```bash
rts-arena run
```

```
第 1 局  种子 3  P0=my-bot  P1=baseline  用时 0.6 秒
  第 1359 tick 结束：P1（baseline）获胜——摧毁了对方全部主基地
  P0 my-bot: 调用 273 次，燃料 平均 0.0 最高 1，报错 0，燃料耗尽 0，被拒命令 0
  P1 baseline: 调用 273 次，燃料 平均 0.1 最高 1，报错 0，燃料耗尽 0，被拒命令 0
  回放：replays\annihilation-…-s3-g1.json
  P0 的日志：replays\annihilation-…-s3-g1.P0-my-bot.log
```

模板 bot 不出兵，输是正常的。读这几行：

- **谁赢、第几 tick、怎么结束的**；
- **每个 bot 的调用次数、燃料、报错、被拒命令**，报错和被拒命令应该一直是 0；
- **回放和日志的位置**：都在 `replays/` 里。日志是每个 bot 各一份，只有它自己的信息，开头还附了一份它视角的战报。

### 燃料是什么

bot 每隔几个 tick 被调用一次，每次能用的计算量是有上限的，这个上限叫**燃料**：

- **怎么计量**：按 bot 实际执行了多少代码算，不按秒算。1 燃料大约是 5000 次简单循环（在一般的电脑上约 0.4 毫秒）。所以不管电脑快慢，同一个 bot 用的燃料都一样，比赛对谁都公平。
- **上限多少**：每次调用的上限写在 `game.fuel` 里，看规则包，多数是 100，复杂的玩法给得多一些（比如拓荒 130、牧野争牛 200）。开局加载时（顶层代码和 `onStart`）有 20 倍，可以在那时做一次性的准备，比如算好地图上的距离。
- **用完了会怎样**：这一次调用立即被打断，**这次下的命令全部作废**，下次调用时 `view.events` 里会有一条 `botError`。bot 不会被踢出比赛，下一次照常调用，但单位这一轮就没收到新命令。
- **在哪看**：`check` 输出里的「燃料最高」，`run` 输出里的「燃料 平均 / 最高」和「燃料耗尽」次数。上面那局模板 bot 最高只用了 1，离上限 100 还很远。

一般的 bot 用不到上限。容易超的写法是每次调用都在整张地图上做搜索（比如对每个单位都算一遍寻路），这类结果应该算一次、存在顶层变量里反复用。

## 6. 看回放

```bash
rts-arena view --open
```

浏览器会打开网页播放器（地址是 `http://127.0.0.1:5180/`，用完在命令行按 Ctrl+C 退出）。

- 空格播放 / 暂停，← / → 单步，拖动平移，滚轮缩放；
- 点一个单位，能看到它当前的命令；右侧是 bot 打印的日志和被拒命令；
- 底栏「视角」可以只看某一方的视野，看到的就是那个 bot 当时知道的东西。

## 7. 看战报

```bash
rts-arena report
```

最新一局的文字战报，分这几节：

- **局势**：每隔 200 tick 双方的钱、收入、分数、各类单位和建筑；
- **关键事件**：第一次交火、建筑放下 / 建好 / 被毁、金矿采完；
- **战斗**：死了 3 个以上的每一仗，时间、地点、双方损失；
- **经济和损失**：采了多少、花了多少、丢了什么、打死了什么；
- **可能的问题**：平台替你找出来的毛病。

刚才那局模板 bot 的「可能的问题」（节选）：

```
- 钱囤着没花：抽样时平均手上留着 563（最便宜的东西才 50）
- 整局没打到过敌人，只挨了打
- 整局没有兵（只有工人），第 1109 tick 起挨打
- 经济差得多：采集约 610，赢家约 1335（看看工人数、采集分配，是不是太早把钱全花在兵上）
```

每一条都直接指向下一步该改什么。

## 8. 让大模型写 bot

在 `my-bot` 目录里打开你的编程 agent（Claude Code、Codex、反重力等都行），给它这样一段话：

```
请读 PROMPT.md，在 bot.ts 里写一个尽量强的 bot。
每改一版都在这个目录里运行 rts-arena check、rts-arena run --games 10 --quiet、rts-arena league、rts-arena report，看结果再改，至少迭代 5 版。
最后告诉我：跑了哪些命令、最后一版的联赛得分率、对每个参考 bot 的胜负。
```

`PROMPT.md` 开头也要求它每版都真的跑对战。验收时看它报的联赛成绩，别只听它说「应该能赢」。agent 说不能运行命令时，就自己在目录里跑 `rts-arena league`，把输出贴给它。

想自己写，看 [写 bot 指南](写-bot-指南.md)。

## 9. 开一场联赛

```bash
rts-arena league
```

你的 bot 和这个规则包所有参考 bot 循环对打（每对 4 局，换边），最后打印：

- 排行榜：胜平负、得分率（带 95% 区间）、等级分；
- 对阵表：谁赢了谁几局；
- 统计和精彩对局，还有你的 bot 没拿到第一的那几局的回放文件名。

局数少时误差很大。想确认新的一版是不是真的变强了：

```bash
rts-arena league --focus --per-pair 10
```

只打你的 bot 对每个参考 bot，每对 10 局，参考 bot 之间不打。

- 自己写 bot：[写 bot 指南](写-bot-指南.md)。

- 换个玩法：再建一个 bot 目录，比如 `rts-arena init frontier`（工人自己建兵营、箭塔、仓库）或 `rts-arena init koth`（夺点）。每个规则包的 `PROMPT.md` 都不一样，换了规则包要重新读。
- 打完一场联赛做成视频：见 [联赛视频指南](联赛视频指南.md)。
