## 交什么

一个 TypeScript 文件，导出 `onTick`，可选导出 `onStart`：

```ts
export function onStart(game: Game): void {
  // 可选，开局调用一次
}

export function onTick(view: View, cmd: Commands): void {
  // 每隔 game.decisionInterval 个 tick 调用一次
}
```

- 只能是单个文件，不能 `import`。所有类型（`View`、`Entity`、`Commands`……）和全局函数（`dist`、`console.log`）都可以直接用，不用导入。
- 只能用"擦掉类型就是 JavaScript"的写法：不能用 `enum`、`namespace`、构造函数参数属性（`constructor(private x: number)`）。
- 顶层变量整局都在，可以用来记状态（比如看到过的敌人位置、每个单位的分工）。
- 不支持异步：`async` 函数、`Promise` 回调、`setTimeout` 都不会被执行。

## 时间与调用

- 游戏按 tick 推进。初始局面是第 0 tick，每隔 `game.decisionInterval` 个 tick 调用一次 `onTick`。
- 你在第 t tick 的局面下发出的命令，在推进到第 t+1 tick 时最先执行。
- 所有玩家看到同一时刻的局面、同时下命令、同时结算，没有先手后手。
- 命令会一直执行，直到完成、失效或被新命令替换。所以不需要每次都给每个单位下命令，只在需要改变时下。

## 每个 tick 的结算顺序

1. 执行各玩家的命令。不合法的命令被拒绝，下次调用时在 `view.events` 里看到 `rejected` 和原因。
2. 生产：每个建筑队列里第一个的剩余时间减 1，减到 0 就出现在建筑旁边最近的空格（周围 4 圈都满了就等）。
3. 战斗：所有冷却好了、射程内有目标的实体同时出手、同时扣血，然后移除生命 ≤ 0 的实体。
4. 移动：冷却好了的单位按随机顺序各走一格。被单位挡住就等，挡久了绕路。
5. 采集：贴着资源点的采集者采集，带着资源贴着交货点的交货。
6. 规则包结算（计分、判胜负）。

## 命令

同一次调用里对同一个单位下多条命令，最后一条生效。

| 命令 | 效果 |
|---|---|
| `cmd.move(u, x, y)` | 走到 (x, y)，途中不还手。目标格不能走或到不了，就走到能到的最近处后停下。 |
| `cmd.attack(u, target)` | 追着打 target，直到它死掉或你方看不见它（之后变成 idle）。 |
| `cmd.attackMove(u, x, y)` | 走向 (x, y)；射程内有敌人就停下来打，视野内有敌人就追过去打，到了变成 idle。 |
| `cmd.gather(u, resource)` | 循环采集：走到资源点旁边采，采满后自动回最近的交货点交货，再回来。资源点采完后交完手上的就停下。 |
| `cmd.stop(u)` | 停下（idle）。 |
| `cmd.produce(b, type)` | 排进生产队列，立即扣资源。队列最多 5 个；单位数（含队列）不能超过 `game.unitCap`。 |
| `cmd.cancel(b)` | 取消队列里最后一个，全额退款。 |

自动攻击：`idle` 和 `attackMove` 状态、能攻击的实体（包括能攻击的建筑）会打射程内的敌人，选最近的，一样近选血最少的，再一样选 id 最小的。`move` 和 `gather` 状态的单位不还手。中立实体不会被自动攻击。

## 坐标、距离、视野

- 格子坐标，左上角是 (0, 0)，x 向右、y 向下。单位只能上下左右走，不能斜着走。
- 距离一律是曼哈顿距离 |dx| + |dy|。多格建筑按占地里最近的那一格算，贴着为 1。全局函数 `dist(a, b)` 就是这个距离。
- 射程、视野、"贴着"都按这个距离。近战射程 1 就是上下左右贴着（斜对角距离是 2，打不到）。
- 一格只能站一个单位。建筑、资源点和不可通行的地形挡路。
- 地形整张图一开始就知道（`game.terrain`）。如果规则包开了战争迷雾，实体只看得到己方任一实体视野范围内的。

## 沙箱限制

- **燃料**：每次 `onTick` 最多用 `game.fuel` 燃料，1 燃料大约是 5000 次简单循环（约 0.4 毫秒）。燃料按这个粒度计，很轻的调用会显示用了 0。用完立即中断，这次的命令全部作废，下次调用时 `view.events` 里有 `botError`。顶层代码加上 `onStart` 共有 20 倍燃料。
- **内存** 128 MB，超了 bot 停止运行（你的单位只会继续执行已有命令）。
- **墙钟**：单次调用超过 2 秒 bot 停止运行。正常代码碰不到，只有对巨大数组排序、拼超长字符串这类不计燃料的内置操作才会。
- 没有 `Date`（调用会抛错，时间用 `view.tick`）、没有网络、文件、定时器。
- `Math.random()` 是固定种子的随机数：同样的两个 bot、同样的种子，重跑结果完全一样。
- `console.log` 写进回放：每次调用最多 20 行、每行 300 字，整局 5000 行。在网页播放器里可以对着画面看。打印大对象会先完整转成 JSON 再截断，很慢而且不计燃料，别打印整个 `view`。
- 每次调用最多发 2000 条命令，多出的丢弃。
- 抛出的错误带行号，就是你源文件里的行号。错误会写进回放，下次调用时也会出现在 `view.events`。

## 本地调试

```bash
npm run arena -- check <规则包> my-bot.ts                       # 类型检查 + 每个位置试打 300 tick
npm run arena -- run <规则包> my-bot.ts bots/<规则包>/rush.ts     # 打一局，写回放
npm run arena -- run <规则包> my-bot.ts bots/<规则包>/rush.ts --games 10   # 打 10 局看胜率（每个种子换边各打一次）
npm run viewer                                                   # 网页播放器看回放
```
